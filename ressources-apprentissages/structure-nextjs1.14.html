📁 Structure Next.js 14

Fiche Récapitulative : Dossiers & Fichiers

🎯 Dossiers Principaux
📂app/
Cœur de l'application — Toutes les pages et API routes vivent ici.
Contient les pages, layouts, components, API routes
Structure = structure URLs (app/tournaments/ → /tournaments)
📂public/
Fichiers statiques — Images, icônes, fichiers téléchargeables.
✓ favicon.ico (icône dans l'onglet du browser)
✓ Images, SVG, autres assets publics
📂node_modules/
Dépendances NPM — Librairies téléchargées automatiquement.
⚠️ NE PAS TOUCHER !
Géré par package.json + package-lock.json
~500MB, souvent ignoré dans Git
🔍 Dans app/ — Structure Importante
📄layout.tsx
Le "template HTML" de ta page — header, footer partagés à tous.
Défini une fois, utilisé pour TOUTES les pages
Idéal pour navbar, navigation globale
📄page.tsx
Une page affichable dans le browser (la vraie page web).
app/page.tsx → / (homepage)
app/tournaments/page.tsx → /tournaments
app/tournaments/new/page.tsx → /tournaments/new
📂api/
Tes API routes (endpoints backend) — reçoivent requêtes HTTP.
app/api/tournaments/route.ts → POST/GET /api/tournaments
app/api/matches/[id]/route.ts → PATCH /api/matches/123
⚙️ Fichiers de Configuration (Racine du Projet)
📋package.json
Le "manuel" du projet — dépendances, scripts, info projet.
✓ npm install ← lit package.json
✓ npm run dev ← exécute le script "dev"
✓ Liste toutes tes librairies (React, Next.js, Tailwind, etc.)
🔒package-lock.json
NE PAS ÉDITER — Verrouille les versions des dépendances.
Généré automatiquement par npm
Garantit que tout le monde a les mêmes versions
🎨tsconfig.json
Configuration TypeScript — comment le code est vérifié.
Défini les règles de typage TypeScript
Ne pas toucher sauf connaissance avancée
🎨tailwind.config.ts
Configuration Tailwind CSS — couleurs, fonts, thème custom.
Ajoute tes couleurs custom, breakpoints, fonts ici
Actuellement : configuration par défaut (ok pour démarrer)
⚙️next.config.ts
Configuration Next.js — images, redirects, variables env, etc.
Actuellement : configuration par défaut (ok pour démarrer)
🚫.gitignore
Dit à Git quoi ignorer — node_modules, .env, build files, etc.
✓ node_modules/ (trop gros, pas besoin)
✓ .next/ (fichiers de build)
✓ .env.local (secrets, API keys)
📄.env.local
SECRET — Variables d'environnement locales (pas en Git).
✓ DATABASE_URL="postgresql://..."
✓ API_KEYS, tokens, secrets
⚠️ Toujours dans .gitignore !

📊 Résumé : Où Mettre Quoi ?
🎨 Une page Web ?
→ app/dossier/page.tsx
⚙️ Une API endpoint ?
→ app/api/route.ts
🧩 Un composant réutilisable ?
→ components/NomComposant.tsx
🔧 Une fonction utile ?
→ lib/fichierUtile.ts
🪝 Une logique React ?
→ hooks/useNomHook.ts
🖼️ Une image/icône ?
→ public/image.png
🎯 L'ESSENTIEL À RETENIR :

✅ app/ = tout ce qui est visible (pages + API)
✅ package.json = recette du projet
✅ node_modules/ = librairies téléchargées (ne pas toucher)
✅ .env.local = secrets (ne pas committer en Git)
✅ Structure des dossiers = structure des URLs
